# Video-Transition-Effects

两段素材之间的转场工具：**交叉淡化（cross-fade）**、**四方向滑动（slide）**
与**擦除（wipe，固定画面 + 移动掩码，方向与软边可配）**，从零实现，
仅依赖 Python 标准库与系统 ffmpeg/ffprobe。

## 核心承诺

- **成片总帧数可推导**：成片总帧数恒为 `Nout = Na + Nb - No`
  （Na/Nb 为两段素材帧数，No 为重叠帧数），比硬接短恰好一个重叠区；
- **重叠区之外一帧不丢**：head 段逐帧对应 A、tail 段逐帧对应 B，
  帧映射在 `plan.py` 显式建账，解码帧数与写出帧数三方核对，不符即报错；
- **转场帧统一走帧读取器**：所有视频帧只经 `FrameReader` 的
  `ffmpeg → rawvideo rgb24` 管道进入 Python，帧序号即时间轴坐标；
- **淡化、滑动、擦除共用同一套帧混合器**：滑动按行切成 A/B 互补条带，
  擦除按掩码切成「纯 B / 软边渐变 / 纯 A」分区，条带/分区内部都调用
  `blend_rgb24_frame`（整数权重），不新增像素通路；
- **边界不露黑边**：滑动两帧满幅互补铺满；擦除掩码分区无缝铺满，
  软边渐变带始终夹在两个纯区之间或画布之外，无未覆盖像素是构造保证；
  首尾锚点位移/边界落在画布外，首帧逐像素等于 A、末帧逐像素等于 B；
- **音视频同帧推进**：视频像素/位移/掩码与音频 PCM 共用同一张帧映射表
  和同一条进度曲线，不会出现「画面动了声音没动」；
- **确定性整数运算**：混合、位移与掩码边界全部用整数（有理数权重 +
  半数远离零取整），结果可逐字节单测锁定。

## 用法

```bash
# 交叉淡化（默认，旧行为）：重叠 0.5 秒（按帧率换算为整数帧）
python -m video_transition a.mp4 b.mp4 -o out.mp4 --overlap 0.5 -y

# 直接指定重叠帧数（语义最精确），输出机器可读账目
python -m video_transition a.mp4 b.mp4 -o out.mp4 --frames 12 --json

# 四方向滑动：B 从右向左推入，速度曲线两头慢中间快
python -m video_transition a.mp4 b.mp4 -o out.mp4 --frames 12 \
    --transition slide --direction left --easing ease_in_out -y

# 擦除转场：B 固定不动、由左向右的掩码逐步揭开，24px 线性软边
python -m video_transition a.mp4 b.mp4 -o out.mp4 --frames 12 \
    --transition wipe --direction right --soft-width 24 -y
```

转场参数：

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| `--transition` | `fade`（默认）/ `slide` / `wipe` | 交叉淡化 / 方向滑动 / 擦除 |
| `--direction` | `right` `left` `down` `up` | 运动方向（slide/wipe 生效），名字描述 B 的推入/揭开方向，默认 `right` |
| `--easing` | `linear` `ease_in` `ease_out` `ease_in_out` | 速度曲线，默认 `linear` |
| `--soft-width` | 非负整数像素（仅 wipe） | 软边宽度，`0`=硬边；超过画面运动轴长度时自动钳制并告警，默认 `0` |

输出示例（逐段账目）：

```
head=63 帧(纯A) + overlap=12 帧(擦除(left,软边24px,ease_in_out)) + tail=38 帧(纯B) = 113 帧；时长 4.520s
```

## 模块结构

| 模块 | 职责 |
| --- | --- |
| `probe.py` | ffprobe 探针，帧率保留 num/den 有理数，音轨有无单独探测 |
| `plan.py` | 纯逻辑时间轴：三段区间、`FrameJob` 取帧指令、转场类型与滑动位移 |
| `easing.py` | 速度曲线：帧号 → 有理数进度与整数像素位移（锚点 0/1、单调） |
| `slide.py` | 四方向滑动几何（互补区域）与逐行合成，复用帧混合器 |
| `wipe.py` | 擦除掩码几何（扩展行程边界 + 软边渐变分区）、软边钳制告警与逐像素合成 |
| `blend.py` | RGB24 像素与 s16le PCM 的整数加权混合原语 |
| `audio.py` | 采样边界累积取整、整轨 PCM 拼装（增益与视频进度同源） |
| `reader.py` | `FrameReader` 帧读取器、s16le PCM 解码（无音轨静音占位） |
| `pipeline.py` | 双路解码线程 + 有界队列 + 编码写入器 + 帧数三方核对 |
| `cli.py` | 命令行入口 |

## 设计要点

### 帧域账本

```
head     A[0, Na-No)        纯 A，Na-No 帧
overlap  A[Na-No, Na)       转场（淡化或滑动），No 帧
         B[0, No)
tail     B[No, Nb)          纯 B，Nb-No 帧
```

淡化、滑动与擦除的取帧坐标完全相同，差异只在重叠帧的渲染方式与附带的
整数位移/掩码边界；总帧数恒等式对三种转场都成立。

### 滑动几何与无黑边保证

重叠区第 k 帧，A 与 B 沿同一运动轴整体平移、互不缩放，位移
`s = eased_shift(k, No, 轴长)`（水平轴长=宽、垂直轴长=高）。
两帧都是满幅，在任意 `s` 下铺满画布的两个互补区域，区域长度之和
恒等于轴长——每个输出像素恰好来自一个源，不存在未覆盖像素。

首尾锚点是精确的：`s=0` 输出逐像素等于 A（与 head 末帧连续）、
`s=轴长` 输出逐像素等于 B（与 tail 首帧连续），边界无跳变帧。

### 擦除掩码、软边与无黑边保证

擦除时 A/B 两帧固定不动，由一条沿运动轴推进的掩码边界揭开 B。
若边界只在 `[0, L]` 内移动，恒宽软边在终点仍压在画布内，末帧到不了
纯 B；因此边界走一条**扩展行程**（`L` 为运动轴长、`soft` 为软边宽度）：

```
edge(k) = round(p(k) · (L + soft)) − soft        # p(k) 为 eased 进度
```

取值范围恰为 `[-soft, L]`：`k=0` 时整条渐变带 `[edge, edge+soft)`
落在画布外、满幅纯 A；`k=No−1` 时渐变带移出另一端画布外、满幅纯 B。
中间帧画布被切成「纯 B / 线性软边 / 纯 A」三个无缝分区，每像素权重
恒在 `[0,1]`，不存在未覆盖像素。掩码边界的进度 `p(k)` 与滑动位移、
音频增益取同一个 `eased_fraction`——**擦除掩码和转场时长共用同一条
时间线**。

`--soft-width 0` 时软边退化为硬边，分区与滑动几何逐字节同构（同帧
A/B、同进度下硬擦除与硬滑动成片一致）。软边宽度只沿运动轴生效，合法
上限即轴长（水平=宽、垂直=高）；超限时钳到轴长并发出
`WipeSoftWidthWarning`（原始值与钳制值都在告警文本里），钳制后渐变
铺满全轴，依旧无黑边、锚点依旧精确。

### 速度曲线

`linear`（等间隔）、`ease_in`（`t²`，慢入快出）、`ease_out`
（`1-(1-t)²`，快入慢出）、`ease_in_out`（分段二次，两头慢中间快）。
全部以有理数 `num/den` 给出，首尾锚点精确为 0/1，位移经半数远离零
取整后夹回 `[0, 轴长]`，不会因取整越界露黑边。

### 音频采样对齐

第 f 帧的采样区间用累积取整边界 `round(f * sr / fps)` 定义，
A、B、输出三条时间轴用同一个函数求值，48kHz 配 NTSC 帧率时
每帧 1601/1602 采样交替也不会漂移。无音轨素材用等长静音 PCM 占位。
滑动/擦除时音频增益跟随同一条速度曲线，与画面推进严格同帧。

### 约束

- 两段素材必须**同帧率、同分辨率**（不做隐式缩放/重采样，避免账本失真）；
- 重叠帧数必须短于任一素材；
- 输出 H.264 + AAC，容器支持 `.mp4`/`.mkv`。
