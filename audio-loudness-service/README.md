# 批量音频响度处理服务 (Audio Loudness Service)

## 项目背景

台里验收口径是 **-23 LUFS**、**真峰值 -1 dBTP**，现有成片过不了。需要做一个批量音频处理服务，一次处理 200 条以上。

## 需求

### 处理流程（一次成片，两遍会二次压缩）

1. **测量** — 先测量输入音频的 LUFS、LRA、真峰值
2. **计算增益** — 根据目标响度计算需要调整的增益量
3. **真峰值限幅** — 应用增益后做真峰值（True Peak）限幅，防止超 -1 dBTP

**不要直接调用 ffmpeg 的 loudnorm 滤镜做两遍**（先测量再归一化 = 两次压缩，会造成二次失真）。必须一次测量 + 一次增益 + 一次限幅完成。

### 目标规格

| 指标 | 目标值 |
|------|--------|
| 综合响度 (Integrated LUFS) | -23 LUFS ±0.5 |
| 真峰值 (True Peak) | ≤ -1 dBTP |
| LRA (响度范围) | 不强制，但输出测量值 |

### 声道处理

- 支持立体声和 **5.1 声道**
- 5.1 必须正确下混为立体声（按 ITU-R BS.775 标准：L/R 各 1.0, C 0.707, Ls/Rs 0.707, LFE 不参与或可选）
- 输出始终为立体声

### 批量处理能力

- 一次处理 200 条以上音频/视频文件
- **并发上限**可配置
- **失败重试**机制（指数退避）
- 单条失败不影响其他任务，能单独重跑指定文件
- 处理进度可视化（日志或进度条）

### 输出报告

每条处理完成后输出前后对比报告（JSON 或 CSV）：
- 输入：LUFS、LRA、True Peak、时长、采样率、声道数
- 输出：LUFS、LRA、True Peak、应用增益量
- 状态：成功 / 失败 / 已跳过

### 验证

用 `ffmpeg -filter_complex ebur128` 或专业工具复核结果。

## 技术栈建议

- Python + ffmpeg（ffmpeg 做音频处理，ebu_r128 做测量）
- 或直接使用 `pyloudnorm` / `libebur128` 库

（也可自由选择其他技术栈）

## 交付要求

- 命令行工具：`audio-loudness input_dir output_dir [--target -23] [--true-peak -1] [--concurrency 8]`
- README 说明算法原理、5.1 下混公式、使用方法
- 支持常见音频格式（wav、mp3、aac、flac）和视频中提取音频（mp4、mov、mkv）
