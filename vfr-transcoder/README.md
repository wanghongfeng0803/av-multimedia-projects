# VFR 转码器 (VFR Transcoder)

## 项目背景

一批老素材是 **VFR（可变帧率）**、时间基 `1/1000`、带 B 帧重排，转完之后片尾音画偏移 200ms 以上。需要做一个专门处理这类源的转码器。

## 需求

### 核心指标

- 输出 **CFR（恒定帧率）**，帧率可配置（默认 25fps 或 30fps，取源文件主流帧率）
- **音画偏移 ≤ 40ms**（首和尾都要测，3 小时长素材首尾都在范围内）
- 保留原始时间戳给监控系统用，`copyts` 语义不能丢

### 源素材特征

- VFR（可变帧率），time_base = 1/1000
- 带 B 帧，有 B 帧重排（需要正确处理 PTS/DTS 顺序）
- 时长从几分钟到几小时不等
- 封装格式多样（mp4、avi、mkv、ts）

### 处理难点

- VFR 转 CFR 需要正确的帧时间戳重映射，不能简单丢帧或复制帧
- B 帧重排导致 PTS 和 DTS 顺序不一致，处理不当会引入音画偏移
- 长素材的累积误差控制（3 小时累积偏移不超过 40ms）
- copyts：输出文件的时间戳基准要和输入一致，方便监控系统关联

### 任务调度与可靠性

- 外层提供 **HTTP 接口**（提交任务、查询状态、获取结果）
- Worker 进程池模式，可横向扩展
- 任务**状态机**：pending → queued → running → completed / failed
- 支持**断点续跑**：转码进度持久化，进程被 kill 后重启能从断点继续，不从头开始
- 失败任务可手动重试

### 测试要求

- 测试用自造的 VFR 长片（自己生成有规律的 VFR 测试素材）
- **30 秒样本不算通过**，至少 30 分钟以上的 VFR 素材才算有效验证
- 验证方法：逐帧比对时间戳误差，首中尾三个点测音画偏移

## 技术栈建议

- Python + ffmpeg（用 subprocess 管道 + ffprobe 做时间戳分析）
- HTTP 框架：FastAPI 或 Flask
- 任务队列：Celery 或自己实现简单的 worker 池
- 进度持久化：SQLite 或 JSON 文件

（也可自由选择其他技术栈）

## 交付要求

- 两个组件：HTTP API 服务 + Worker 进程
- 命令行也能直接跑：`vfr-transcoder input.mp4 output.mp4 [--target-fps 25]`
- README 说明：VFR→CFR 算法、音画同步保障机制、copyts 实现、断点续跑设计、状态机流转
- 附带 VFR 测试素材生成脚本和音画偏移校验脚本
